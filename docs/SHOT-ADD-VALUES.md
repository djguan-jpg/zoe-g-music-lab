# 新增鏡頭的時間來源

新增鏡頭先讀取最後一鏡的原結束欄；有效有限非負十進位值作為新鏡開始，再加既有六秒草稿長度。原鏡時間、創作原文、人物狀態、列身份與展開狀態保留。新鏡人物狀態接續原文，其餘創作與母題留待人類填入，作品總長不自動改動。

入口以既有 `MusicPlanningValues.trim` 判斷Python欄位空白，再用原 `nonnegativeNumber` 解析非空值。BOM／零寬與包住數字的C0 separators屬無效數字；NEL可以是欄位空白，也可以是合法數字周邊空白。分類不改寫原字串，Unicode十進位、原底線文法、有限數字與負下溢拒絕沿同一parser。

最後一鏡結束留白或鏡頭清單為空，保持原0–6秒起草行為。這只提供新列，沒有補齊原鏡時間或確認全片連續；仍須完成各鏡創作、人工校時並檢查時間／影格與資料連戲。

無效數字拒絕後保留全部原列、總長、列序列、刪除紀錄、成果與音檔。可以明確修正原結束欄，再按同一新增控制；只有成功才新增列、標記分鏡編修並移至新鏡。busy、1000鏡容量與其他集合控制沿既有規則，沒有新增網路或Agent能力。

實際handler回歸在 `tests/test_collection_busy.js`；原版3項失敗與ChromeBOM錯誤新增／NEL拒絕收據在本輪忽略QA。純parser、app adapter、完整測試、ChromeDOM與確切來源封裝各有獨立接受；不能以VM或待辦為零冒充實際畫面、保存檔或媒體接受。
