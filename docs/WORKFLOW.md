# 使用問題、修改與發佈流程

自 2026-10-15 起採用本流程。之前把小修拆成大量 PR、版本與重複封裝，卻太晚驗證創作者能否接續使用。分層提交仍保留，工作單位改為一個能驗收的使用問題。

## Issue 與 PR 怎麼選

| 情況 | 做法 | 結束條件 |
| --- | --- | --- |
| 想法、用途不明、待研究或尚未重現的問題 | 先記一個 Issue；已有相同問題就更新原 Issue | 決定值得做、延後或停止，留下依據 |
| 一個已確認問題需要程式或文件修改 | 開一個 PR，連結原 Issue；相關修正放同一分支 | 實際輸出符合該問題的驗收條件 |
| 同一功能的 bug、審閱修正、操作指南與測試補齊 | 在原 PR 以分層 commit 接續 | 不因每個 commit 另開 PR 或提升版本 |
| 純說明修正或投稿狀態更新 | 更新現有合適的 PR；沒有現有 PR 才另開一份必要的文件 PR | 文件與實際狀態一致，不發產品版本 |
| 已合併功能需要撤銷 | 先辨識仍有問題的行為；必要時提出明確 revert PR | 驗證撤銷影響，不重寫公共 Git 歷史 |

Issue 用來記錄問題與決策，PR 用來審查具體差異。合併 PR 與關閉 Issue 的原因必須符合實際完成狀態；尚有創作者或跨工具接受待驗時，保持對應 Issue 開啟。

## 先驗證有沒有用

開始實作前寫明使用者、允許使用的素材、目前成熟工具的做法、卡住的步驟、預期輸出及可觀察的成效。私密素材只在授權範圍使用；公開 Issue 與 PR 不放歌名、歌詞、素材、來源路徑或登入資料。

目前只驗證字幕交付、PCM WAV 核對與原素材交接。舊編輯器維持隱藏。先用同一件作品比較成熟工具原流程與本工具流程，記錄人工步驟、花費時間、失敗及修正次數：輸出能在目標工具接續、原素材保持，且至少減少一個必要人工步驟而不增加修正成本，才有繼續擴張的理由。沒有省事就縮減或停止該功能。

格式解析、SHA 與合成測試只能證明其測試範圍；跨工具 GUI、實聽、完整視覺與創作者接受要分別記錄。不能用模組數、版本數、排行榜或測試數代替實用性。

## 驗證、審閱與發版

1. 保留修改前的提交與必要外部狀態備份；把純邏輯、UI／I/O、驗證與文件分層提交到同一 PR。
2. 開發期間做受影響的必要檢查。文件與範本更新核對內容、連結及 diff；不為此重跑整套產品測試、掃描或封裝。
3. 程式內容穩定後，完成既定完整測試與必要的實際操作驗證。失敗先定位；只因新變更、失敗或未解決疑點才重跑相關檢查。
4. 修改後的正式產品來源依指定 AI Security Scanner 流程另作實際掃描，由使用者從 desktop 啟動；逐筆審閱指定 run。舊 run、doctor、plan 或另一份來源不能代替。
5. 發版前對確切 source commit 建立並核對封裝；合併、tag、遠端 asset 與接受狀態分開記錄。未達條件維持 Draft，不以候選封裝宣稱新 head 已接受。產品版本只在準備交付時決定，同一候選的修正不另升版。

作者自測、獨立審閱與創作者接受分別列出；自己合併不算外部審閱。正式發版的完整來源要求保持，這次文件更新不替代 v0.174.0 的待辦接受。

Scanner doctor 的 `prerequisite` 可能是固定先決條件說明，不能單因非空就宣稱 WSL 未就緒。須分別核對 `available`、`phase`、`detail` 及官方操作要求；有語意衝突就記錄衝突，不改寫成實際環境故障，也不換工具繞過桌面啟動要求。v0.5.0 的 [status_value 原始碼](https://github.com/teddashh/ai-security-scanner/blob/v0.5.0/src-tauri/src/managed_runtime.rs#L4290-L4312) 將 prerequisite 從 target 設定複製，與執行狀態分開。

## 投稿與證據管理

一個公開工具保留一份準確介紹；多個 Skill 可以留在同一 Repo，不因內部模組或版本再投稿一次。更新既有介紹前先確認它仍符合一般 UI 的實際能力，公開候選不能描述成已發布功能。

2026-10-15 核對四個既有公開頁：名稱相同、來源版本為 3、管理連結指向同一專案，介紹仍是 v0.171.0 舊編輯流程。平台只提供該作品所有分享版本一起撤下的控制；已依使用者要求撤下並保留帳號內內容。待實用性接受完成，再預覽一份準確介紹；本輪不重送原作認領、不宣稱平台核實創始身分。

每個問題保留一份簡短接續、必要的前後狀態與指定 source 證據。收據與私密 QA 留在 Git 外，失敗不覆寫；不為未改變的狀態不斷產生完整副本。清理仍只處理明確自有、可還原且符合既定條件的項目，最新三正式版、未知／partial／FAILED 與私密素材保持。歷史 PR 和 release 不為降低榜單件數而刪除。
