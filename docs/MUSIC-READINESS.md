# 歌曲欄位待辦（v0.30）

按「檢查歌曲待辦」查看目前歌曲的必填欄位、數值範圍及交付清單。點選一項會定位原欄位；段落待辦也會選取同一段。建立歌曲包及從目前歌曲預覽分鏡起稿，會先檢查並定位第一項。沒有補寫文字、改動數字、重排段落或呼叫模型。

## 欄位與範圍

- 歌名、記憶點、故事核心、曲風與聲音、人聲表現、聽眾及語言必填；已有歌詞可留白。
- BPM 為 20–300 的有限數字，每小節拍數為 1–12 整數。
- 每段名稱、敘事任務及聲音配置必填；小節為 1–128 整數，能量為 1–5 的有限數字。至少一段，最多 40 段。
- 避免事項可以完全不列；已新增的項目不可只有空白。交付清單至少一項，每種清單最多 100 項。

文字空白與數字文法沿用共用 Python 領域規則：文字的 U+0085 是空白，U+FEFF 保留；數值只接受有限十進位，支援既有 Unicode 十進位數字與合法數字間底線，拒絕布林、null、十六進位及非有限值。原欄位保持字串，不以 JavaScript 的空字串轉零代替檢查。HTML BPM 使用 step=any，120.0004 可交給既有完整服務，保持精度。

## 檢查結果的生命週期

檢查保存本頁的原始歌曲快照，包含可留白的歌詞及完整清單。段落穩定 ID 也參與定位快照；即使同名或所有文字相同，移動後仍不能使用舊列位置。編修、新增、刪除及移動使舊待辦停用，重新檢查後恢復。定位前再讀目前來源，攔截未發出 input 事件的變動。

其他工作台和音檔不參與歌曲快照。明確載入範例、歌曲需求、草稿或保存版本，以及撤回歌曲替換，清除被替換工作台的暫態待辦。歌曲輸入處理中可編修；檢查及待辦按鈕暫停，晚回應仍由既有來源與 revision 保護拒絕。

全部項目計數，診斷最多保存前 200 項，介面呈現前 20 項並明示截斷。filledSections 只計算各段欄位，不能推定全域欄位或作品通過。

## 分層

| 層 | 責任 |
|---|---|
| planning-values.js | 從本專案既有 planning-source 提取純文字空白與有限十進位規則；planning-source、需求清單與兩種創作待辦重用 |
| music-readiness.js | 原始 draft3 歌曲形狀、Unicode／8 MiB 上限、必填與數值診斷；固定欄位順序與原列號 |
| readiness-state.js | 注入 capture／source／inspect／onState 的暫態快照控制器；歌曲與分鏡共用，定位前重查、隔離回傳與 inspector 副本 |
| app.js | 讀取原 DOM／穩定列 ID、安全文字呈現、aria-invalid、焦點及 busy；不接受外部待辦報告 |
| planning-review／application／domain | 原有完整歌曲、總長、分鏡起稿、需求來源與主要 JSON 核對；HTTP／CLI／JSON-lines／MCP 共用 |

產品版本 0.30.0；Agent protocol 1、MCP 2025-11-25、草稿 3 及各領域 schema 各自保持。七個基本工具／啟庫十二工具不變。沒有新 operation、依賴、模型、登入或外網呼叫；待辦、列 ID 與檢查快照不進草稿或 wire。

## 完整驗證仍須執行

待辦零只表示這些欄位檢查通過。40 段各 128 小節、12 拍、20 BPM 的欄位皆有效，推得總長仍超過完整服務上限，建立歌曲及起稿會拒絕。實際聲音、演唱、咬字、音畫、素材授權和創作品質仍由實作與人工核對。檔案 Agent 起稿獨立核對自己的來源，不依目前歌曲的留白重新推算。
