# 歌曲段落順序（v0.29）

在歌曲設計的「要調整的段落」選一列，按「向前移動」或「向後移動」。名稱、小節、能量、敘事任務及聲音配置整列移動；可以移動尚未填完的段落，建立成果時仍須通過完整驗證。同名段落使用本頁穩定列識別，選項另顯示目前位置，不以名稱判斷身分。

「撤回段落移動」只還原最近一次移動的順序。撤回時重新讀目前每列內容，因此保留後來修改的文字、小節與能量。新增、刪除、還原段落、其他順序變更或載入歌曲後，先前紀錄失效；不以整份表格快照覆蓋新編修。刪除還原與載入撤回是各自獨立的功能。

移動後歌曲成果標示過期，須重新建立。新的歌曲計畫依表格順序重算固定 BPM 的各段時間；新的分鏡時間起稿也使用同一順序。既有分鏡保持原狀。已預覽的本機歌曲起稿在排序改變後不能直接套用，須重新預覽。Agent 起稿檔保留其自己的來源，先核對預覽再明確套用；沒有自動替換歌曲。

## 分層與狀態

- `web/music-arrangement.js`：純 `move`／`restore`，最多40列、五個原始字串欄位、唯一穩定ID。只交換鄰近位置，不清理文字、解析數字或推測創作。
- 同模組注入 `capture`／`apply`／`onState` controller：保存一份順序紀錄；刷新及撤回前核對完整ID順序。其他工作台及媒體不參與排序來源；欄位編修不使順序撤回失效。
- `web/app.js`：DOM捕捉、重繪及選取同一列，處理中停用排序／新增，更新草稿與成果狀態。控制列在橫向表格外，手機可直接操作；新增段落選取並聚焦新列。
- 原有 `planning-source`／`planning-review` 與共用 application/domain：核對完整建立及需求回讀；CLI／HTTP／JSON-lines／MCP沿用相同歌曲與起稿契約。

ID、選取、移動紀錄不進 draft3、成果JSON或Agent wire。產品0.29與Agent1、MCP2025-11-25、各領域schema分開；七基本／啟庫十二工具保持。無新operation、依賴、模型、網路或媒體處理。

段落能量仍是創作設計，時長仍假設固定速度、沒有弱起或自由速度。排序及資料通過不表示音樂已生成、實唱／實聽或成片已驗收。見 [本輪QA](QA-v0.29.0.md)。
